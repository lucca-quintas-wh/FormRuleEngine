data-visible-when

Mostra ou esconde o elemento onde o atributo está. É o único plugin que age no próprio elemento em vez de procurar um input dentro dele — por isso funciona tanto num <input> quanto numa seção inteira.

Dependências: nenhuma

1. O caso básico

A condição é lida a cada mudança de qualquer campo citado nela. Aqui o elemento escondido é um <div> com dois campos dentro.

2. Esconder um campo isolado

O atributo pode ir direto no <input>. Note que só o input some — o <label> continua lá, porque a engine esconde exatamente o elemento que carrega o atributo. Na prática você quase sempre quer o atributo no wrapper do campo.

3. Modificadores

Três atributos ajustam como o elemento aparece e some. Todos são lidos do dataset do próprio elemento, não da condição.

AtributoPadrãoEfeito
data-animate="false"animado Desliga o fade de 0,2 s ao aparecer. Útil em listas longas, onde N fades simultâneos pesam.
data-keep-space="true"não reserva Esconde com visibility: hidden em vez de display: none: o espaço continua ocupado e o layout não pula.
data-clear-on-hide="true"preserva Limpa todos os campos de dentro ao esconder, disparando change em cada um. Evita enviar dados de um ramo que o usuário abandonou.

4. Condições compostas

A mesma gramática de todos os *-when. A página 03 cobre a DSL inteira; aqui só o formato.

5. Um campo pode controlar vários blocos

Não há limite nem ordem: a engine monta um mapa de dependências campo → elementos no registro do plugin, e ao mudar um campo reavalia só os elementos que o citam. Não há varredura do formulário inteiro a cada tecla.

6. Elementos fora do formulário

O bootstrap adota elementos com data-visible-when que estão fora do <form> — o caso real são painéis de um drawer declarados pelo controller. A guarda importante: ele só adota o que não pertence a outro formulário, senão dois formulários aninhados esconderiam as seções um do outro.

Este bloco está fora do <form> e mesmo assim reage ao campo Plano lá de cima.

7. Evento emitido

Toda vez que a visibilidade muda, o elemento dispara visibility:changed (borbulhando), com detail.visible. O painel de eventos abaixo está escutando esse evento — é assim que o plugin step sabe que uma etapa inteira sumiu. 

form.addEventListener('visibility:changed', (e) => {
  console.log(e.target, e.detail.visible);
});

Cuidado: esconder um campo não o remove do envio. O display:none não desabilita nada, e um campo oculto continua sendo serializado com o valor que tinha. Se o ramo abandonado não pode ir para o servidor, use data-clear-on-hide="true" — ou combine com data-disabled-when, já que campo desabilitado não é enviado.
