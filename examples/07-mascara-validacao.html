data-mask-when · data-validate-when

Máscara que troca junto com o tipo do documento, e validação client-side declarada por regra nomeada. Os dois usam o formato "lista de regras": a primeira que casar vence, e nenhuma casando significa remover o efeito.

Dependências: jQuery + jquery.mask (máscara) · validate não precisa

1. Máscara condicional

O caso clássico: o mesmo campo recebe CPF ou CNPJ dependendo do tipo de pessoa. A máscara é reaplicada apenas quando muda — o plugin lembra a última aplicada por input e sai cedo se for a mesma.

É a sintaxe do jQuery Mask Plugin, que é quem faz o trabalho. Nestes exemplos, quem responde é o substituto mínimo em assets/jquery-shim.js — cobre 0 9 A S e literais, o suficiente para demonstrar.

Formatos aceitos em mask

"mask": "000.000.000-00"                       // string: o padrão direto
"mask": {"pattern":"00/00/0000","options":{}} // objeto: repassa options ao plugin

2. Máscara que some

Quando nenhuma regra da lista casa, o plugin chama unmask(). É como se libera um campo que aceita formato livre em determinado contexto.

A máscara não valida. Ela formata enquanto se digita; um CPF mascarado pode ser 111.111.111-11. E o valor enviado ao servidor vai com os separadores — se o backend espera só dígitos, limpe lá ou mantenha um hidden com a versão crua.

3. Validação declarativa

validate_when não valida na hora: ele marca o input com a regra que deve valer, gravando data-validate-rule, data-validate-params e data-validate-message, mais a classe form-rule-validated. Quem executa é o seu validador de formulário, chamando plugin.validateField(input).

Registrar o seu

O plugin expõe registerValidator(nome, fn). A função recebe (value, params) e devolve booleano. 

const validate = window.formVisibilityManager.engine.plugins.get('validate');
validate.registerValidator('cpf', (value) => digitosValidos(value));

Nesta página registramos cpf assim mesmo — teste no campo abaixo (use 111.111.111-11 para ver falhar).

Como conectar ao seu submit

O plugin foi escrito para ser chamado por um validate() global já existente. Em código novo, o gancho é este: 

form.addEventListener('submit', (e) => {
  const plugin = engine.plugins.get('validate');
  const campos = form.querySelectorAll('.form-rule-validated');
  const ok = Array.from(campos).every(el => plugin.validateField(el));
  if (!ok) e.preventDefault();
});

validateField() devolve booleano, alterna a classe form-rule-invalid, escreve a mensagem no title do campo — e devolve true com aviso no console se a regra nomeada não estiver registrada, para não travar o formulário por causa de um erro de digitação no nome.
