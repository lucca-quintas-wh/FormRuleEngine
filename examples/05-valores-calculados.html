data-set-value-when · data-computed-when

Os dois plugins que escrevem em campos. Ambos gravam por nome (target / chaves de values), não no elemento onde o atributo está — o que significa que o atributo pode morar em qualquer lugar do formulário.

Dependências: nenhuma

1. Definir valor por template

values é um mapa campo → template. No template, {OutroCampo} é substituído pelo valor atual daquele campo. A regra reavalia sempre que qualquer campo citado (no template ou na condição) muda.

2. Definir valor sob condição

Com condition, a escrita só acontece enquanto a condição vale. Quando ela deixa de valer, o plugin não desfaz — o último valor escrito permanece. Se você precisa limpar, use uma segunda regra com a condição inversa e template vazio.

Sobrescreve o que o usuário digitou. A regra roda a cada mudança de dependência, e não sabe se o valor atual veio dela ou de uma pessoa. Para campos que o usuário também edita, prefira copy_when (que guarda o valor original) ou lock_when (que trava e restaura).

3. Expressões aritméticas

computed_when com expression: o template é resolvido e, se o resultado contiver apenas números e + - * / ( ) . ,, é avaliado como aritmética. Qualquer outro caractere faz o plugin devolver a string resolvida como está — o que transforma o mesmo mecanismo em concatenação de texto.

Não coloque a regra que escreve X e a regra que lê X no mesmo elemento. As dependências são calculadas por elemento: se um data-computed-when tem {"target":"Subtotal"} numa regra e {Subtotal} na outra, então Subtotal vira dependência do próprio elemento. Gravar nele dispara change, que reavalia o elemento, que grava de novo — laço infinito, e a aba trava. 

<!-- TRAVA: Subtotal é escrito e lido pelo MESMO elemento -->
<div data-computed-when='[
  {"target":"Subtotal","expression":"{Quantidade} * {ValorUnitario}"},
  {"target":"Total","expression":"{Subtotal} - 10"}]'>

<!-- certo: um elemento por elo da cadeia -->
<div data-computed-when='{"target":"Subtotal","expression":"{Quantidade} * {ValorUnitario}"}'>…</div>
<div data-computed-when='{"target":"Total","expression":"{Subtotal} - 10"}'>…</div>

A regra prática: agrupe no mesmo atributo apenas cálculos irmãos (que leem as mesmas origens); separe os que formam uma cadeia. Vale para set_value_when pelo mesmo motivo.

Por que não é eval livre. A expressão só é executada depois de passar por /^[0-9+\-*/ ().,]+$/. Um valor de campo com letras não vira código: cai no ramo de texto. Ainda assim, a substituição acontece antes do teste — então trate expression como parte do seu template server-side, não como algo que o usuário final compõe.

4. Números no formato brasileiro

Campo mascarado como 1.234,56 quebra qualquer aritmética. Duas chaves resolvem: parse: "br" normaliza a entrada (1.234,56 → 1234.56) e format: "br" devolve o resultado com duas casas e separadores brasileiros.

5. Idade a partir da data de nascimento

type: "age" — anos completos, lendo dd/mm/aaaa do campo em source. Rejeita data inexistente (31/02 devolve vazio em vez de virar 03/03) e conta o aniversário do ano corrente.

6. Faixa etária

type: "age_band" converte a idade em faixa. Sem a chave bands, as faixas saem das opções do próprio campo de destino, cujo valor codifica o intervalo ("24.28" = de 24 a 28). É o que permite trocar a tabela de faixas no servidor sem tocar em JS.

Com faixas explícitas, o formato é este — e lt cobre o "abaixo de":

{"target":"Faixa","type":"age_band","source":"Nascimento",
 "bands":[{"lt":18,"value":"menor"},
          {"min":18,"max":59,"value":"adulto"},
          {"min":60,"value":"idoso"}]}

7. Diferença entre datas

type: "days_between" devolve dias inteiros entre start e end, nunca negativo. Aceita dd/mm/aaaa e também o que o Date nativo entender (inclusive o aaaa-mm-dd de um <input type="date">).

8. Cálculo condicional

Com condition, o cálculo só roda quando ela vale. Fora disso o campo fica como estava — o plugin devolve undefined e setFieldValue nem é chamado.
